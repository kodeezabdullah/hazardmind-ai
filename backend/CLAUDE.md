# HazardMind Backend — CLAUDE.md

## My Role
Backend orchestrator for HazardMind AI.
Drives the 4-agent LangGraph pipeline (satellite -> hazard -> impact -> report).
Exposes REST API to frontend. No external chat-room service — see root
`CLAUDE.md` for the completed Band -> LangChain migration.

## CRITICAL RULE
event_id = UUID generated ONCE in router.py's `/analyze` handler.
Never regenerated by any agent — threaded through `PipelineState` unchanged.

## Tech Stack
FastAPI + Python 3.12
Neon PostGIS (asyncpg)
LangGraph `StateGraph` (backend/graph.py)

## API Endpoints
POST /analyze         -> Start pipeline
GET  /status/{id}     -> Check progress
GET  /results/{id}    -> Final results
GET  /pipeline-log/{id} -> errors/anomalies/confidence_scores trail
GET  /health          -> Health check

## Pipeline Flow
User -> POST /analyze
     -> event_id = UUID4()
     -> INSERT disaster_events
     -> asyncio.create_task(orchestrator.start_pipeline(...))
     -> graph.ainvoke(initial_state) drives satellite -> hazard -> impact -> report
     -> Return {job_id: event_id} immediately (pipeline runs in the background)

## Progress Steps
1. received  -> POST called
2. satellite -> Agent 1 processing
3. hazard    -> Agent 2 processing
4. impact    -> Agent 3 processing
5. report    -> Agent 4 processing
6. complete  -> All done
7. failed    -> Error

## Database Tables
disaster_events   <- Backend writes (status/step + pipeline_log JSONB)
satellite_results <- Agent 1 writes (from within its own node)
hazard_zones      <- Agent 2 writes
impact_data       <- Agent 3 writes
final_reports     <- Agent 4 writes

## Key Files
- `graph.py` — `build_pipeline_graph()`. Each agent's `node.py` is loaded via
  an isolated `importlib` loader (`_load_node`) because `agent.py` /
  `intelligence.py` / `node.py` / `hf_app.py` exist under MULTIPLE agent
  directories with the same bare module name — a normal `import` would clobber
  `sys.modules` between agents. Each load temporarily prepends only that
  agent's own directory to `sys.path`, so its unqualified sibling imports
  resolve within its own tree.
- `orchestrator.py` — `OrchestratorAgent.start_pipeline()` builds the initial
  `PipelineState`, calls `graph.ainvoke()`, persists the final
  errors/anomalies/confidence_scores trail via `db.update_pipeline_log()`, and
  sets the terminal `disaster_events` status.
- `router.py` — HTTP routes; `/analyze` fires `start_pipeline` as a background
  `asyncio.create_task` so the request returns immediately (frontend polling
  behavior unchanged).
- `db.py` — asyncpg pool + DB read/write helpers (contracts unchanged from
  pre-migration; `insert_satellite_result` was dead code — post-migration the
  satellite node writes its own row directly — and was removed).
- `cleanup.py` — periodic stuck-event GC only (the Band backlog-drain half is
  gone with Band).

## Failure handling
Each node returns `status: "failed"` (with an `errors` entry) instead of
raising on a stage failure. `graph.py`'s conditional edges route straight to
`END` the moment `state["status"] == "failed"`, so the graph never runs a
downstream stage on top of a broken upstream result — this replaces the old
Band orchestrator's `handle_failure()` early-return.
